# Интеграция SMART BUY AI с API Реферальной программы Яндекс Маркета

Статус: подготовка завершена частично; ожидается API-ключ и параметры площадки от Яндекс Маркета.
Дата проверки документации: 2026-11-17.

## Важное разграничение API

Для договора Дистрибуции/Реферальной программы используется API Реферальной программы Маркета (Affiliate API), а не API кабинета продавца. Это разные продукты и разные права доступа.

Affiliate API предназначен для получения доступных в рамках программы данных, создания реферальных ссылок/артикулов и получения статистики заказов. Он не является общедоступным API всего каталога Маркета и не гарантирует возможность выгружать произвольный полный каталог для ценового сравнения.

Документация:
- https://yandex.ru/support/market-distr/ru/api
- https://yandex.ru/support/market-distr/ru/api/reference/get-partner-link-create
- https://yandex.ru/legal/market_affiliate_api/ru

## План подключения после выдачи доступа

1. Получить от менеджера/личного кабинета API-ключ именно для API Реферальной программы.
2. Получить идентификатор площадки `place_id` или `clid` (тип «Партнерские ссылки»).
3. Уточнить доступные блоки данных и методы, лимиты запросов, а также одобренные площадки (сайт и Android-приложение).
4. Хранить ключ только в секретах Render; не в APK, GitHub, логах или клиентских ответах.
5. Реализовать серверный клиент с таймаутами, ограничением частоты, безопасной обработкой ошибок и кешированием в пределах правил Яндекса.
6. Начать с генерации реферальных ссылок для конкретных товарных URL через `GET https://api.content.market.yandex.ru/v3/affiliate/partner/link/create`.
7. Сохранять для карточки товара ссылку, название/изображение/цену/остаток/вознаграждение только в пределах разрешённого ответа и условий договора.
8. Подключать другие методы (поиск/данные товаров, артикулы, статистика, маркировка ERID) только после проверки их доступности в выданном профиле доступа и действующей документации.

## Предварительные параметры окружения

- `YANDEX_MARKET_AFFILIATE_TOKEN` — секретный ключ Affiliate API (ожидается).
- `YANDEX_MARKET_PLACE_ID` — идентификатор одобренной площадки (ожидается; если Яндекс выдал CLID, использовать согласованный с документацией параметр).
- `YANDEX_MARKET_API_ENABLED` — выключено до получения и проверки доступа.

Не создавать переменные для seller Partner API (`Api-Key`) без отдельного договора/доступа именно к API продавцов.

## Обязательные ограничения отображения

Перед включением данных в приложении проверить условия договора и актуальные правила Яндекса. В частности, действующая редакция соглашения Affiliate API требует:
- использовать данные только в рамках одобренного сайта/программы, доступных бесплатно и открыто; регистрация сама по себе допустима, но платный доступ к данным — нет;
- не скрывать и не изменять передаваемые данные, товарные знаки, логотипы, ссылки и уведомления; рядом с данными указывать «Данные сервиса Яндекс Маркет» со ссылкой на https://market.yandex.ru/ и показывать логотипы, как требует соглашение;
- показывать данные только на страницах, относящихся к соответствующим товарам;
- не изменять сортировку данных Яндекса; дополнять данными других источников можно только если это не искажает данные и не вводит пользователя в заблуждение;
- показывать данные, соответствующие местоположению конечного пользователя, и предоставить автоматическое определение или выбор города;
- не размещать на тех же страницах стороннюю контекстную рекламу/рекламные сети; исключение в соглашении — Рекламная сеть Яндекса;
- не использовать данные на платных страницах/в платной части приложения.

Поэтому до проверки договора нельзя показывать Яндекс-данные в Premium-only разделах или рядом с рекламой сторонней рекламной сети. Нельзя считать договор разрешением на произвольное копирование всего каталога.

## Проверка после получения ключа

- Проверить токен тестовым разрешённым запросом согласно текущему руководству API.
- Проверить, что `place_id`/CLID относится к одобренной площадке SMART BUY AI.
- Проверить ответы 401/403, лимиты и корректную обработку ошибок.
- Создать одну тестовую реферальную ссылку для разрешённого товара и проверить переход.
- Только после этого включать источник в production и помечать его как подключённый.

До завершения проверок источник должен отображаться как «Ожидает API-доступ», а не как активный источник товаров/цен.
